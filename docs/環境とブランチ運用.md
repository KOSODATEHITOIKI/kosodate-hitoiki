# 環境とブランチ運用ガイド

このプロジェクトにおける「ビルドモード」「Gitブランチ運用」の考え方をまとめたドキュメントです。

## 2. 環境(Flavor: dev / prod)について

導入済み(2026-09-30)。姉妹プロジェクトのdev/stg/prod 3種とは異なり、本プロジェクトはdev/prodの2種のみとする。

| Flavor | 用途 | Android applicationId | アプリ名 |
|---|---|---|---|
| dev(Development) | 開発者が自由に壊していい環境 | `com.kosodatehitoiki.dev` | ひと息(dev) |
| prod(Production) | 本番。絶対に壊さない | `com.kosodatehitoiki` | ひと息 |

エントリーポイントは`lib/main_dev.dart` / `lib/main_prod.dart`(`lib/main.dart`は引数なし起動時のデフォルトとしてdevに委譲)。VS Codeの「実行とデバッグ」には`.vscode/launch.json`でdev/prodの2構成を用意済み。

```bash
flutter run --flavor dev -t lib/main_dev.dart
flutter run --flavor prod -t lib/main_prod.dart
```

Supabaseの接続先(`lib/core/config/supabase_config.dart`)はFlavorごとに切り替える。devは専用のSupabaseプロジェクトに接続する。prodのプロジェクトは未作成で、接続先はプレースホルダーのまま(prodで起動すると接続先未設定のエラー画面になる)。

## 3. ブランチ戦略: Git Flow(develop運用)

```
main                      ← リリース済み(本番公開済み)の状態のみを反映
  └─ develop              ← 開発中の最新コードを集約する統合ブランチ
       ├─ feature/xxx     ← 機能開発(developから分岐・developへマージ、短命)
       └─ fix/xxx          ← 不具合修正(developから分岐・developへマージ、短命)
  └─ hotfix/xxx           ← 本番の緊急修正(mainから分岐、mainとdevelopの両方へマージ)
```

- 通常の開発は`develop`から`feature/xxx`・`fix/xxx`を切り、`develop`宛にPRを作成する
- `main`は「今ストアに出ている状態」を表す。リリース時に`develop`の内容を`main`にマージし、`vX.Y.Z`タグを打つ
- 本番で緊急の不具合が出た場合のみ`main`から`hotfix/xxx`を切り、修正後に`main`と`develop`の両方へ反映する
- 全てのPRはレビュー必須(最低1名の承認)

### 運用フロー(開発中)

```bash
# 1. developから機能ブランチを作成
git checkout develop
git pull
git checkout -b feature/xxx

# 2. 実装・コミット後、developへPR
git push origin feature/xxx
# → PR作成(base: develop) → CIが自動でtest/analyze実行 → レビュー → developマージ

# 3. リリース時: developの内容をmainへ反映し、タグを打つ
git checkout main
git merge develop
git tag v1.0.0
git push origin main v1.0.0
```

### 役割整理

| | 役割 |
|---|---|
| main | リリース済み(本番)の状態 |
| develop | 開発中の最新状態(次回リリース候補) |
| feature/xxx・fix/xxx | 個々の機能・修正作業(短命) |
| hotfix/xxx | 本番の緊急修正(短命) |

未定: CI/CDの自動デプロイ設定(deploy-stg.yml等)、Flavor構成。実装を進めながら追記する。

## プッシュ通知(Firebase)

- **Firebaseプロジェクトは、dev・本番で1つ(`kosodate-hitoiki-f0036`)を共用する**(2026-10-28決定)。プッシュ通知(FCM)だけに使い、解析・クラッシュ収集・広告のツールは入れていない。通知の送り先は、アプリの登録ごとに分かれる(dev=`com.kosodatehitoiki.dev`、本番=`com.kosodatehitoiki`)ので、混ざらない。
- 設定ファイル(`google-services.json`)は、環境ごとに、ローカルに置く(リポジトリには入れない。`.gitignore`で除外)。
  - dev: `android/app/src/dev/google-services.json`
  - 本番: `android/app/src/prod/google-services.json`(共用のため、中身は、dev・本番の2つのアプリを含む同じファイルでよい)
- ファイルがない環境(CIなど)では、プッシュ通知だけが使えず、アプリは動く。
- サービスアカウントの鍵(`FCM_SERVICE_ACCOUNT_JSON`)は、**同じプロジェクトのものを、dev・本番のSupabaseそれぞれの Edge Functions のシークレットに登録**する。リポジトリ・チャットには置かない。
- iOS(フェーズ2): 同じプロジェクトにiOSアプリ(`com.kosodatehitoiki`)を追加し、`GoogleService-Info.plist`を置く。
