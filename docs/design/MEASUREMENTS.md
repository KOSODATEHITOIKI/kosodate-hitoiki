# デザイン寸法・比率の観察記録

確認日: 2026-10-14。対象は `docs/design/README.md` に記載された最終版24枚（S-01〜S-14と送信前チェック）。初期案・写真追加案・送信前チェックのシンプル版は比較対象に含めない。

この記録はPNGの視認による概算。幅・高さは画像上のpxで、端末のdpやFlutterのfontSizeではない。座標・寸法には通常±8〜16px、淡い背景・装飾には±20〜30px程度の読み取り幅がある。元のフォント名、フォントサイズ、字間、透明な余白、正確な角丸半径はPNGだけでは確定できない。小数点までの精密なデザイン仕様として使わない。

## 1. 測定基準とスケール領域

- 23枚の画像ファイルは **941×1672px**。端末内の表示領域はおおむね **x=85〜855、y=54〜1606**、幅 **W≈770px**。端末の黒い外枠・画像外側の余白は実装のスケール対象に含めない。
- 例外の `S-03_投稿詳細_ただ聞いてほしい.png` は **1024×1536px**。表示領域はおおむね **x=132〜891、y=58〜1480**、幅 **W≈759px**。この画像は別の基準で扱う。
- 下端のホームインジケーター、上端の時刻・カメラ部分はOS領域。アプリで模写せずSafeAreaを使用する。
- 標準画像のボトムナビは **y≈1467〜1565**。その下にホームインジケーター領域がある。カードをこのy座標へ固定しない。
- 画像pxから幅比への変換は **要素幅÷W**。例: 730pxのカードは表示領域の約95%。
- 幅390 logical pxを仮の比較基準にするなら **画像寸法×390÷770**。730px→約370、96px→約49。ただし390は実機の確定設計幅ではなく、比較用の基準にすぎない。

## 5. 固定を避ける実装方針

1. スケール領域は端末枠を除いた利用可能幅を基準とし、全画面で同じ外側余白・カード幅のルールを使う。幅770pxをそのまま固定しない。
2. 幅比はカードや大きな装飾の参考にする。文字・操作領域まで画面全体のTransformやFittedBoxで一律縮小しない。
3. 高さは文章・文字拡大・入力エラー・キーボードで変わる。カード、行、ボタンは最小サイズと内側余白を使い、本文の自然高を優先する。
4. 横2列・3列の領域は利用可能幅と文字の大きさで切り替える。チップはWrap、反応カード・プロフィール・相談カードは必要に応じて縦配置。
5. 太陽の光線込みの大きさと画像ファイル全体のサイズは一致しない。画像内部の透明余白を確認し、本文側の幅を削りすぎない。
6. タブ画面は共通ナビの上まで、ナビなしの認証・通報・退会画面はSafeArea下端までをスクロール領域とする。OS領域を二重に加算しない。
7. 大きい画面のコンテンツ最大幅・ブレークポイント・余白上限は今後の描画比較で決める。この画像群にはタブレット・横向きの確定案がない。
8. 検証幅は320／360／390／430／768 logical px、横向き、文字拡大1.0／1.5／2.0、キーボード表示を候補にする。これは検証案であり既存テストの実施報告ではない。

## 6. モック間の差・未確定事項

- S-03「ただ聞いてほしい」は画像比率・3タブ・文言「共感だけほしい」が他の案と異なる。5タブと反応モードの正式文言は全体設計書の決定を優先。
- S-03やS-07の反応件数は表示例。件数を誰に見せるかは全体設計書の仕様と照合する。
