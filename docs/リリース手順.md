# リリース手順(Android)

Androidのアプリを、Google Playに出すための手順。iOSは、フェーズ2(Apple Developer Programの加入後)。
署名鍵・パスワードは、運営だけが持つ。リポジトリ・チャットには、置かない。

## 1. 署名鍵を作る(初回だけ。運営の作業)

```bash
keytool -genkey -v -keystore hitoiki-upload.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

- 質問に、キーストアのパスワード・鍵のパスワード・名前などを答える。**パスワードは、必ず控える。**
- できた `hitoiki-upload.jks` は、**リポジトリの外**(例: `C:\Users\<あなた>\keys\`)に置く。
- **鍵とパスワードを、複数の安全な場所にバックアップする**(パスワード管理ツール、別の媒体など)。なくすと、アプリを更新できなくなる場合がある。
- ここで作る鍵は「アップロード鍵」。Google Playの「Play App Signing」(推奨)に登録すれば、万一、アップロード鍵をなくしても、Googleに申請して、差し替えられる。

## 2. 鍵の場所を、アプリのビルドに教える

1. `android/key.properties.example` を、`android/key.properties` にコピーする。
2. 鍵の場所とパスワードを書く(`storeFile` は、`/` 区切りで書く)。
3. `android/key.properties` は、リポジトリに入らない(`.gitignore`で除外)。

署名鍵(`key.properties`)がないと、本番のリリースビルド(prod release)は、**失敗する**(debug鍵のアプリを、誤って配るのを防ぐため)。

## 3. 本番のビルドを作る

```bash
flutter build appbundle --release --flavor prod -t lib/main_prod.dart
```

- できるもの: `build/app/outputs/bundle/prodRelease/app-prod-release.aab`(Google Playに上げる形式)
- 確認用に、端末へ入れるなら: `flutter build apk --release --flavor prod -t lib/main_prod.dart`
- バージョンは、`pubspec.yaml` の `version: 1.0.0+1`(`+`の後ろが、ビルド番号。**Google Playに上げるたびに、増やす**)。

## 4. ビルドの前に、確認すること

| 項目 | 確認 |
|---|---|
| 本番の接続先 | `lib/core/config/supabase_config.dart` の prod が、本番のプロジェクト(設定済み) |
| 規約の版数 | `lib/core/config/terms.dart` の prod に、決まった版が入っている(**未決のままだと、本番の登録で失敗する**) |
| プッシュ通知 | `android/app/src/prod/google-services.json` がある(なくても、アプリは動く。通知だけが使えない) |
| 規約・ポリシー | アプリ内の仮の文面を、公開ページへのリンクに置き換え済み |
| アイコン・起動画面 | `python tool/generate_app_icons.py` で書き出し済み(コミット済み) |
| ディープリンク | 本番のビルドで、パスワード再設定・Googleログインが、アプリに戻れる |

## 5. Google Play Console

1. 登録する(初回のみ、登録料25ドル。本人確認に、日数がかかることがある)。
2. アプリを作る(アプリ名「ひと息」、言語、無料/有料、カテゴリ)。
3. 「Play App Signing」を有効にする(推奨)。
4. 必要な申告を行う: プライバシーポリシーのURL、データの安全性(収集するデータ・共有する外部サービス)、コンテンツのレーティング、対象年齢、広告の有無(なし)、アカウント削除のURL(アプリ内の「退会」、および、Webからの削除の案内)。
5. まず「内部テスト」に`.aab`を上げて、実機で確認する。問題なければ、「製品版」に進める。

### データの安全性の申告で、書くこと(参考)
- 収集: メールアドレス、ニックネーム、投稿・コメント、端末の識別子(プッシュ通知)。
- 共有する外部サービス: Supabase(保存)、OpenAI(投稿前の自動チェック)、Google(ログイン・プッシュ通知)、Resend(認証メール)。
- 解析・クラッシュ収集・広告のツールは、入れていない。

## 6. リリースのあと

- Gitで、`develop` を `main` にマージして、`vX.Y.Z` のタグを打つ(`docs/環境とブランチ運用.md`)。
